# 浏览器扩展验收流程

适用于 Chrome MV3 开发版扩展的功能和界面验收。

## 1. 基础检查

先运行与改动相关的自动化检查：

```bash
npm test
npm run typecheck
npm run build
```

## 2. 启动扩展

1. 运行 `npm run dev`，记录 WXT 实际使用的端口。
2. 确认生成的 manifest CSP 与开发服务器端口一致。
3. 在 `chrome://extensions/` 中加载或重新加载开发扩展。

如果端口变化后没有重新加载扩展，扩展页可能因 CSP 拦截而显示空白。

## 3. 从真实入口进入

最终验收必须点击浏览器工具栏中的扩展图标，确认打开或复用了：

```text
chrome-extension://<extension-id>/dashboard.html
```

不能用普通网页或 Chrome API 测试桩代替真实扩展入口。

使用 Agent 验收时：

- 工具栏图标由人工或 computer-use 点击；
- 页面内容的观察、交互、断言和截图使用 ego-browser 完成。

## 4. 复现并验证

1. 按用户描述的最短路径复现问题。
2. 记录复现步骤、前置状态、实际结果和预期结果。
3. 修复后重新加载扩展，重复相同路径。
4. 针对具体症状执行明确断言，不能只检查页面是否报错。
5. 检查相邻功能，避免引入明显回归。

可根据问题类型选择验证手段：

- 交互问题：检查点击、输入、选择和页面跳转结果。
- 视觉问题：检查位置、尺寸、层级和溢出，并截图留证。
- 状态问题：刷新或重开 Dashboard，检查状态恢复。
- 后台问题：检查 Service Worker、消息和持久化结果。
- 网络问题：检查请求、响应和错误提示。

## 5. ego-browser 操作原则

1. 使用独立任务空间并在整个验收过程中复用。
2. 先用 `snapshotText()` 或截图观察页面，再执行操作。
3. 每次关键操作后重新读取页面状态。
4. 必要时用 `js()` 读取 DOM、计算样式或应用状态并断言。
5. 保存关键截图，完成后调用 `completeTaskSpace(..., { keep: false })`。

## 6. 验收收尾

1. 确认自动化检查和浏览器验收均通过。
2. 保存必要的断言输出和截图。
3. 关闭 ego-browser 任务空间并停止开发服务器。
4. 检查 `git status --short`，清理本次验收产生的临时构建文件。
5. 简要记录操作路径、预期结果、实际结果和检查结果。
